# Sheet Happens Design System

Use `components.md` in the workspace root as the visual inventory. This app implements that inventory with typed React components, Tailwind v4 tokens, shadcn-style owned source, Radix primitives, Storybook stories, and automated checks.

## Component contract

- Functional components only.
- Export explicit prop types.
- Use `variant`, `size`, `tone`, `state`, and `density` for visual variants.
- Use discriminated unions for workflow statuses.
- Keep `className` intentional and documented by the component API.
- Use Lucide icons, not inline SVG strings or emoji.

## Testing contract

- Stories document all public variants and important states.
- Interactive components include `play` tests.
- Accessibility checks run through Storybook a11y.
- Route flows run through Playwright.
- Pure helpers and schema logic use Vitest.

## Current library slice

The current Storybook includes reusable primitives for actions, forms, overlays, tables, feedback, and status display. It also includes product-specific Sheet Happens blocks for auth/onboarding, dashboards, weekly time entry, timesheets, admin review, management, reports, settings, payslips, and the design tweaks panel.

These product blocks are intentionally visual and API-first. They establish layout, state naming, props, and Storybook coverage before the app routes and server data paths are built.
